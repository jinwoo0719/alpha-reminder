# B북거래소 구축 청사진 (개인용 선물거래 플랫폼 버전)

> 이 문서는 **실서비스/규제 준수 목적이 아닌, 개인이 혼자 사용하는 선물거래 시뮬레이션/운영 플랫폼**을 전제로 작성됨.
> 따라서 KYC, 규제 대응, 복잡한 컴플라이언스 항목은 제외하고 **실제 동작에 필요한 핵심 기능** 위주로 단순화함.

## 1) 목표
- 비트코인/알트코인 선물거래 화면과 주문/포지션 기능 구현
- 바이낸스 가격/호가를 받아 거래소 형태의 UI 제공
- 일반 웹 수준의 회원가입/로그인 구현
- 어드민에서 회원 정보/잔고를 쉽게 관리(수동 증액 포함)
- 청산 이후 관리자 수동 입금(크레딧 보정) 시나리오를 빠르게 처리
- 디자인은 OKX 스타일의 깔끔한 다크 UIUX 지향

---

## 2) MVP 범위 (반드시 필요한 것만)

### 2.1 사용자 기능
1. 회원가입/로그인
   - 이메일 + 비밀번호
   - 비밀번호 재설정(이메일 코드)
2. 선물거래
   - 심볼: BTCUSDT, ETHUSDT 우선
   - 주문: 지정가/시장가
   - 레버리지 설정(예: 1~20x)
   - TP/SL(선택)
3. 실시간 마켓 데이터
   - 바이낸스 WebSocket 기반 가격/호가창/최근체결
4. 포지션/손익
   - 진입가, 현재가, 미실현손익, 청산가
   - 포지션 종료 및 체결내역
5. 잔고
   - USDT 가상잔고 기반
   - 거래 가능 잔고/사용 증거금 표시

### 2.2 어드민 기능
1. 회원 관리
   - 회원 목록, 검색, 계정 활성/비활성
2. 잔고 관리(핵심)
   - 사용자 잔고 수동 증액/감액
   - 조정 사유 메모 기록(예: "청산 보정")
3. 거래 관리
   - 사용자별 주문/포지션/체결 조회
4. 설정
   - 심볼 ON/OFF
   - 심볼별 최대 레버리지
   - 수수료율

## 3) 단순 아키텍처 (개인 운영 최적화)

## 3.1 구성
- Frontend: Next.js + TypeScript + Tailwind
- Backend API: FastAPI 또는 NestJS
- DB: PostgreSQL
- Cache: Redis (시세 캐시/세션)
- Market Worker: 바이낸스 WebSocket 수신기(별도 프로세스)

## 3.2 구조 원칙
- 처음부터 마이크로서비스로 쪼개지 말고 **모놀리식 + 워커 1개**로 시작
- 운영 단순화를 위해 Docker Compose 기반으로 배포
- 복잡한 메시지 브로커(Kafka)는 초기 제외

---

## 4) 핵심 도메인 설계

## 4.1 주요 테이블
- `users`: id, email, password_hash, status, created_at
- `wallets`: user_id, asset(USDT), balance, available_balance
- `orders`: user_id, symbol, side, type, qty, price, status, created_at
- `positions`: user_id, symbol, side, qty, entry_price, liq_price, leverage
- `trades`: order_id, price, qty, fee, executed_at
- `balance_adjustments`: user_id, amount, reason, admin_id, created_at
- `admin_logs`: admin_id, action, target_user_id, payload, created_at

## 4.2 주문/포지션 규칙(간단 버전)
- 주문 상태: `NEW / FILLED / CANCELED / REJECTED`
- 미체결 엔진을 복잡하게 만들지 않고,
  - 시장가: 즉시 체결
  - 지정가: 기준가 도달 시 체결
- 가격 기준: 바이낸스 최신 가격 + 슬리피지 최소 룰

## 4.3 청산 처리
- 계정 증거금이 유지증거금 이하가 되면 청산
- 청산 직후 어드민에서 `balance_adjustments`로 즉시 잔고 보정 가능
- 청산/보정 이력은 반드시 `admin_logs`에 남김

---

## 5) 어드민 잔고 보정 플로우 (요청사항 반영)
1. 어드민이 사용자 상세 페이지 접속
2. 현재 잔고/열린 포지션/최근 청산 이력 확인
3. "잔고 조정"에서 금액 입력 (+/-)
4. 사유 입력 (예: `청산 후 재시작 자금 지급`)
5. 저장 시
   - `wallets.balance` 업데이트
   - `balance_adjustments` 이력 생성
   - `admin_logs` 감사 로그 생성

이 플로우를 최우선으로 구현하면, 사용 중 발생하는 청산 이슈를 즉시 운영으로 복구 가능.

---

## 6) UIUX 가이드 (OKX 스타일)
- 다크 테마 + 포인트 컬러(초록/빨강)
- 트레이딩 메인 레이아웃
  - 좌측: 심볼 리스트
  - 중앙: 차트
  - 우측: 호가창 + 주문창
  - 하단: 포지션/주문내역
- 어드민 레이아웃
  - 상단 KPI: 전체 잔고, 활성 유저, 오늘 청산 횟수
  - 본문: 회원 테이블 + 잔고 조정 모달

---

## 7) 제외 항목 (이번 버전)
- KYC/신분 인증
- 규제/법무/여행규칙 대응
- 실제 온체인 입출금
- 보험기금/ADL/복잡한 리스크 엔진
- 멀티레벨 레퍼럴 정산

> 필요하면 이후 버전에서 단계적으로 추가.

### 2주차

### 3주차
- 청산 로직
- 어드민 회원 조회/잔고 조정

### 4주차

- UX 다듬기(OKX 스타일 마감)
