# B북거래소 구축 청사진 (선물거래 + 레퍼럴 + 자산관리 + 어드민)

## 1) 목표
- 비트코인/알트코인 **선물거래**를 지원하는 CEX(중앙화 거래소) 형태의 서비스 구축
- 초기 유동성/가격 신뢰도를 위해 **바이낸스 시세·호가 데이터 연동**
- 사용자 성장 장치를 위한 **레퍼럴 시스템**
- 입출금/잔고/리스크를 포함한 **자산관리 기능**
- 운영자가 계정·자산·거래를 제어할 수 있는 **어드민 백오피스**
- 디자인 방향: **OKX 스타일의 미니멀/다크 기반 UIUX**

---

## 2) MVP 범위 (1차 출시)

### 사용자 기능
1. 회원가입/로그인
   - 이메일 + 비밀번호 + OTP(2FA)
   - KYC 레벨(미인증 / 기본인증 / 고급인증)
2. 선물거래
   - USDT-M 무기한 우선
   - 지정가/시장가, 레버리지, TP/SL
   - 포지션/미체결/체결내역
3. 마켓 데이터
   - 실시간 가격, 호가창, 체결 스트림
   - 캔들 차트(TradingView 위젯 또는 자체)
4. 자산
   - 입금 주소 발급, 입금 감시, 내부 전송, 출금 신청
   - 계정 잔고(가용/격리/교차/미실현손익)
5. 레퍼럴
   - 초대코드/링크 생성
   - 수수료 리베이트 정책(예: 20% 기본, 등급별 확장)
   - 추천 현황 대시보드

### 운영 기능(어드민)
1. 사용자 관리
   - 계정 잠금/해제, KYC 승인/반려, 위험도 플래그
2. 자산 관리
   - 입출금 승인 정책, 출금 보류/취소
   - 핫월렛 알람(잔고 임계치)
3. 거래/리스크 관리
   - 심볼별 최대 레버리지/유지증거금율 설정
   - ADL/청산 엔진 상태 모니터링
4. 레퍼럴/정산
   - 리워드 집계, 수동 보정, 지급 이력 감사

## 3) 권장 아키텍처

## 3.1 서비스 구성
- **Web/App Frontend**: Next.js (TypeScript) + Tailwind + Zustand/React Query
- **API Gateway**: 인증/권한/레이트리밋/요청 추적
- **User Service**: 계정, 인증, KYC 메타
- **Market Data Service**: 바이낸스 WebSocket 수신/정규화/캐시
- **Order Service**: 주문 접수/검증/매칭 라우팅(초기엔 외부 가격 참조 기반)
- **Risk Service**: 마진 계산, 강제청산 트리거
- **Wallet Service**: 온체인 입출금/컨펌 감시/내부장부 반영
- **Referral Service**: 추천 트리, 수수료 분배, 정산
- **Admin Service**: 백오피스 API
- **Notification Service**: 이메일/텔레그램/앱푸시

## 3.2 데이터 스토어
- **PostgreSQL**: 계정/주문/체결/정산/레퍼럴 정합 데이터
- **Redis**: 세션, 실시간 시세 캐시, 랭킹/쿼터
- **Kafka(or NATS)**: 주문/체결/리스크 이벤트 스트림
- **Object Storage(S3)**: KYC 파일, 감사 리포트

## 3.3 외부 연동
- 바이낸스 Spot/Futures WebSocket (호가·틱·펀딩·마크가)
- 체인 노드(BTC, ETH, TRON 등) 또는 커스터디 벤더(Fireblocks 등)
- KYC 벤더(예: Sumsub/Onfido)

## 4) 거래소 핵심 도메인 설계

## 4.1 주문/포지션
- 주문 상태: `NEW -> PARTIALLY_FILLED -> FILLED / CANCELED / REJECTED`
- 포지션: 심볼, 방향(Long/Short), 진입가, 수량, 미실현손익, 청산가
- 마진 모드: 격리/교차
- 레버리지: 심볼별 상한 적용

## 4.2 리스크 엔진
- 유지증거금율(MMR), 초기증거금율(IMR)
- 계정 위험도 = (총자산 - 유지증거금) / 포지션 익스포저
- 청산 플로우
  1) 경고
  2) 부분청산
  3) 전량청산
  4) 보험기금/ADL

## 4.3 가격·호가 소스 정책
- 기준 가격: 바이낸스 Mark/Index 우선
- 내부 체결 엔진과 가격 괴리 허용치 설정(예: ±0.2%)
- 장애 시 페일오버 정책
  - 마지막 유효 가격 TTL
  - 소스 단절 시 신규 레버리지 주문 제한

---

## 5) 레퍼럴 설계
- 추천 구조: 1레벨 기본, 필요시 멀티레벨(최대 2~3레벨)
- 보상 이벤트: 거래 수수료 발생 시점
- 정산 주기: 실시간 적립 + 일배치 확정
- 악용 방지
  - 자기추천/순환추천 차단
  - 동일 디바이스/IP/패턴 탐지
  - 비정상 거래량 리워드 보류

---

## 6) 자산관리(월렛/원장) 설계
- **이중 원장(Double-entry ledger)** 필수
  - 사용자 계정, 수수료 계정, 보험기금 계정 분리
- 입금
  - 컨펌 수 도달 후 가용잔고 반영
- 출금
  - 위험 점수 기반 자동/수동 승인
  - 대량 출금, 신규 주소, 고위험 국가 룰 적용
- 정합성
  - 온체인 잔고 vs 내부 장부 일일 대사
  - 불일치 알람 및 출금 서킷브레이커

---

## 7) 어드민 페이지 IA(정보구조)
1. 대시보드
   - 총 거래량, 활성 사용자, 출금 대기, 리스크 경보
2. 회원 관리
   - 회원 검색, 상태 변경, KYC 문서 검토
3. 거래 모니터링
   - 실시간 포지션 위험도, 대량 포지션 추적
4. 자산/출금 승인
   - 신청 목록, 리스크 스코어, 승인 로그
5. 레퍼럴 관리
   - 코드별 유입/거래/보상 리포트
6. 시스템 설정
   - 수수료, 레버리지, 심볼 on/off, 공지관리
7. 감사 로그
   - 관리자 액션 이력(누가/언제/무엇을)

---

## 8) OKX 스타일 UIUX 가이드
- 다크 테마 기본 + 높은 대비의 액션 컬러
- 정보 위계
  - 좌측: 마켓/심볼
  - 중앙: 차트
  - 우측: 호가창/최근체결
  - 하단: 주문·포지션·체결내역
- 인터랙션
  - 주문 전 예상 청산가/수수료 즉시 표시
  - 위험 레벨 컬러 배지(정상/주의/위험)
  - 키보드 단축주문(고급 사용자)
- 성능
  - 호가창 가상 스크롤, 초당 다건 업데이트 최적화

---

## 9) 보안·컴플라이언스 체크리스트
- 인증: 2FA, 디바이스 바인딩, 로그인 이상탐지
- 권한: RBAC(운영/재무/CS/감사)
- 자산: 핫/웜/콜드 월렛 분리, 출금 멀티시그
- 데이터: PII 암호화(AES-256), 전송 TLS1.2+
- 감시: SIEM 연동, 이상거래탐지(FDS)
- 규제: 국가별 VASP/특금법/여행규칙(해당 시)

## 10) 단계별 개발 로드맵

### Phase 0 (2~3주): 설계/기반
- 도메인 모델/DB 스키마
- 인증/권한/감사로그 프레임워크
- 바이낸스 마켓데이터 수집기 PoC

### Phase 1 (4~6주): 트레이딩 MVP
- 주문/포지션/손익/청산 최소 기능
- 기본 웹 트레이딩 화면
- 입금/출금 요청 + 어드민 승인

### Phase 2 (3~4주): 성장/운영
- 레퍼럴 + 리워드 정산
- KYC/리스크 점수 고도화
- 어드민 리포트/알람 체계

### Phase 3 (지속): 안정화
- 모니터링/APM/SLO
- 부하테스트/침투테스트
- 법무/컴플라이언스 정비
